## 中文研究底稿

### 问题、情境与合理解释

用户面对一份下载资料时，可能希望整理最近活动但保留资料，也可能想删除不再需要的下载文件、回收它占用的空间。“清理下载”可能指向两种不同对象，先保留这两种意图，不预设列表清空就代表文件删除。

本期比较同一台电脑、同一份已完成下载且仍保存在本机的文件。桌面 Chrome 的记录清理是已核查的现有方案；独立删除文件或明确一次处理两者，是可比较的任务选择和产品设计方案，不声称 Chrome 当前一定提供某个组合按钮。情境为分析例子，不是采访或亲历。

### 事实与对应来源

| 已核查事实 | 来源 | 本文使用边界 |
| --- | --- | --- |
| 从下载历史点 Remove 会把项目从 Chrome 下载页移除，但不从电脑删除已保存文件。 | [1] Computer 帮助页的下载列表段落。 | 记录消失不能证明文件消失。不套用 Android 或 iOS 操作。 |
| 清除浏览数据中的 Download history 删除的是下载文件列表，实际文件不被移除。 | [2] Download history 类别说明。 | 不能把这个类别的清理当作已回收下载文件内容的空间；也不否认历史数据库自身可能改变。 |
| 下载托盘可提供 Show in Folder 等附加动作。 | [1] 下载后提示。 | 可从记录定位文件，不承诺所有版本每个入口完全一样。 |
| 下载 API 的 erase 清理历史对象而不删除文件，removeFile 是单独文件操作；exists 信息可能滞后。 | [3] erase、removeFile、DownloadItem.exists。 | 支持历史数据与文件状态可分别管理。不能据此断言原生下载页何时刷新、显示什么提示。 |

### 解释、选择与取舍

| 选择 | 可能收益 | 代价和失败条件 |
| --- | --- | --- |
| 只移除活动记录 | 用户可以整理近期列表并继续保存资料。 | 若用户真正要删除文件，完成这个动作仍不足以达成目标；移除便捷入口也可能增加日后定位资料的成本。 |
| 单独处理文件、保留或另行处理记录 | 可针对不再需要的内容管理空间，并分别决定是否保留历史。 | 用户同时想清理两者时可能需要额外步骤。 |
| 明确的一次处理两者方案 | 若用户目标确实包含记录和文件，可能减少操作。 | 如果用户只是整理列表，会超出目标；必须说明处理两者，不能把组合结果藏在含糊的清理名称里。 |

表中的收益、成本和组合方案是作者分析，没有实测。不是建议现有 Chrome 自动增加破坏性行为，而是对任务匹配的比较。删除文件的结果取决于实际文件位置和存储服务；本文不描述永久擦除、云端连带删除或恢复保证。

### 反例与竞争解释

认真检查的反例是“用户就是想把最近活动列表清爽一点，同时保留工作资料”。在这个情境下，Chrome 的分离行为符合目标，清空列表不应被判为失败。由此把判断收窄为先确定所处理的对象，而不是要求所有清理都删除文件。

相反，如果用户希望回收下载文件内容所占的空间，只移除历史记录仍保留文件，就不能用列表行数减少来证明完成。这里谈的是下载文件内容，并非声称清理记录绝不改变任何历史数据库字节。

另一种可能解释是，用户从历史中移除了文件的便捷入口，但文件早已搬到别处，或由其他程序改动。API 的 exists 字段也明确可能不是实时状态。[3] 这支持“活动记录不等于当前存储清单”的边界，但本次未验证原生界面具体如何处理移动或删除后的记录，不将它写成亲见结果。

### 新增认识、适用范围与可检验判断

[P48](../P0048-onedrive-free-space-offline-access/research.md) 讨论文件仍可见但可能不能离线打开。本篇增加记录消失但文件仍保留的相反方向，帮助区分“记录一次事件的对象”与“目前保存内容的对象”。这给下载管理器、最近打开列表、导入历史等产品提供可用判断：动作名称应让用户知道记录、文件或两者会改变。其他产品的实际规则仍需各自核查。

可检验假设：对同时呈现记录与保存内容的界面，明确动作对象，可能提高用户选择与目标的一致性。可在同意参与的原型测试中固定同一条已完成下载与文件，随机比较笼统的清理名称和明确的对象说明。分别给出整理活动但保留资料、删除文件以回收其占用两种任务，记录对文件是否保留的预测、动作选择、完成时间，以及任务后对应文件状态。只看空列表或点击完成不足以验证。

若用户已能准确理解范围，额外文案只增加耗时，应保留更简洁的表达；若两种目标高度重合且用户理解组合结果，一次处理两者也可能更合适；若主要障碍是找不到实际保存位置，应改善定位路径而不只改动作名。此处没有实验结果，不声称具体改写提高完成率。

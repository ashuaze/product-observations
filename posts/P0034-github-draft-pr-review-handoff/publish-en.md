### 1/5

1/5 Two questions get bundled into "share": Can you see what I'm working on? And do I need you to act on it? GitHub's draft pull requests give those questions different answers.

### 2/5

2/5 You can share a draft PR, but you can't merge it. GitHub waits until you mark it ready to automatically request review from the relevant code owners. Any required approvals still apply. https://docs.github.com/en/pull-requests/reference/pull-requests

### 3/5

3/5 Say you're changing checkout and need to decide whether existing carts keep their prices. Share the draft and ask the person who can make that call. Once the whole change is ready for useful feedback, request a full review.

### 4/5

4/5 A draft can still benefit from fast feedback. GitLab runs the same pipelines on draft and ready merge requests by default. A failing test can help the author while the change is still taking shape. https://docs.gitlab.com/user/project/merge_requests/drafts/

### 5/5

5/5 When you add a Ready button, decide whose work it starts. Track review time spent on changes already slated for rewrite, and time authors spend blocked on decisions. If fewer reviews mean longer waits, give drafts a way to ask for specific help.

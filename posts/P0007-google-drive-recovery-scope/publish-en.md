### 1/5

1/5

Recovery design has a blast-radius problem.

Undo works for one action. Version history works when you know which file is wrong. Neither scales well when a sync error or ransomware changes hundreds of files.

The recovery unit should match the failure unit.

### 2/5

2/5

Google Docs lets editors inspect changes, restore an earlier version, or copy it.

Copy is useful when you need old content without replacing today's state. Recovery is not always “go back.” Sometimes it is “compare before deciding.”

https://support.google.com/docs/answer/190843?hl=en

### 3/5

3/5

For PDFs, images, and other non-Google files in Drive, an older version may be deleted after 30 days or after 100 newer versions. “Keep forever” pins it.

A recovery feature can exist while the recovery point you need has already expired.

https://support.google.com/drive/answer/2409045?hl=en

### 4/5

4/5

Google Drive now has a beta bulk restore tool for the last 25 days of revisions. It can roll back multiple non-Google files, but you cannot select individual files.

Older copies become current versions; existing versions are not deleted.

https://support.google.com/drive/answer/16482799?hl=en

### 5/5

5/5

Trash keeps deleted Drive files for 30 days.

Use:
- undo for an action
- history for one overwritten file
- bulk restore for mass changes
- trash for deletion

Match recovery to the failure. Preserve newer versions so recovery can be recovered.

https://support.google.com/drive/answer/1716222?hl=en

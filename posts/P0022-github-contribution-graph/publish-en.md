### 1/5

1/5 A progress metric is also a definition of what counts. GitHub’s contribution graph gives developers a daily activity signal—but not every kind of work earns a green square. Once the square becomes a goal, users can optimize the signal instead of the outcome.

### 2/5

2/5 GitHub counts some commits, issues, PRs, reviews and discussions—but under rules. A commit needs a linked email, a standalone repo, and the default or gh-pages branch. Useful work outside the schema can stay invisible.

https://docs.github.com/en/account-and-profile/reference/profile-contributions-reference

### 3/5

3/5 GitHub used to display daily code-streak counters. In 2016 it removed them, saying profiles should focus on work rather than the duration of activity.

That created a natural experiment: what happens when the visible reward disappears?

https://github.blog/news-insights/product-news/more-contributions-on-your-profile/

### 4/5

4/5 A 2021 study of 433k developers found that long streaks, weekend activity and one-contribution days fell after the counter disappeared. Some “100 Days” participants also stopped streaking.

Behavior changed; work quality wasn’t measured.

https://doi.org/10.1109/ICSE43902.2021.00058

### 5/5

5/5 Visible streaks can support a chosen learning goal; some people kept streaking without GitHub’s counter. The test is alignment:

Does the signal improve the target outcome—or mainly create one-action days and off-hours work?

What useful work does your metric exclude?

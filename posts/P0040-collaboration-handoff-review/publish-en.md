### 1/5

1/5 "Ready" is a risky word in a launch checklist. The designer may mean the mockup is ready to inspect. The marketer may hear that the email can go out. Before adding another status, ask what someone should do when they see it.

### 2/5

2/5 GitHub draft PRs let people see work before code owners are automatically asked to review. Figma Dev Mode can leave a handoff badge unchanged when the value of a variable already applied to a layer changes. Check both who acts and what they act on.

### 3/5

3/5 PagerDuty pauses escalation when someone acknowledges an incident. The incident is still open. Asana does the reverse for one shared task: complete it in one project and it's complete in all of them. Share a checkmark when everyone means the same thing by done.

### 4/5

4/5 For the same launch, keep one Done for final screenshots if both boards track that deliverable. Give the email its own task if it needs separate sign-off. Drafting can start early; sending may be the only step that needs the screenshots.

### 5/5

5/5 Run the handoff twice: once as planned, once after a change of plan. Ask the recipient who acts next, what they're working from, and what would let them stop. Add a status only if it helps them make a better call. Track missed work and extra check-ins.
